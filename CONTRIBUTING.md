# Contributing to The Black Protocol

> **Welcome, operator.** If you're reading this, you're considering joining a mission. Here's how we operate.

## 🎯 Before You Start

1. **Read the [Code of Conduct](CODE_OF_CONDUCT.md)** — Respect is non-negotiable.
2. **Check existing issues** — Your idea might already be in the pipeline.
3. **Join the discussion** — Don't go dark. Talk to the squad first.

## 🚀 How to Contribute

### Reporting Bugs

If you find a bug, open an issue with:

- A clear, descriptive title
- Steps to reproduce
- Expected vs. actual behavior
- Screenshots (if applicable)
- Your environment (OS, browser, version, etc.)

Use the label `bug` when creating the issue.

### Suggesting Features

Have an idea? Open an issue with:

- A clear description of the feature
- Why it would be useful
- Any potential implementation ideas

Use the label `enhancement` when creating the issue.

### Submitting Code (Pull Requests)

1. **Fork** the repository
2. **Create a branch** for your feature or fix:
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/bug-description
   ```
3. **Make your changes** — Keep commits clean and focused
4. **Write clear commit messages**:
   ```
   feat: add dark mode toggle
   fix: resolve login redirect loop
   docs: update API reference
   refactor: simplify auth middleware
   ```
5. **Push to your fork** and open a Pull Request
6. **Fill out the PR template** (if provided) and link any related issues

## 📝 Code Standards

- Follow the existing code style of the project
- Write meaningful variable and function names
- Add comments where logic is complex
- Include tests for new features when applicable
- Ensure your code passes existing tests

## 🏷️ Branch Naming

| Prefix | Use For |
|--------|---------|
| `feature/` | New features |
| `fix/` | Bug fixes |
| `docs/` | Documentation updates |
| `refactor/` | Code refactoring |
| `chore/` | Maintenance tasks |

## 💬 Communication

- Be respectful and constructive in reviews
- Ask questions if something is unclear
- Don't take feedback personally — we're all here to ship better code
- Celebrate wins, learn from losses

## ⚡ Quick Checklist Before PR

- [ ] Code follows project style
- [ ] Commit messages are clear
- [ ] No unnecessary files included
- [ ] Related issue is linked (if applicable)
- [ ] I have read the Code of Conduct

**Questions?** Open a discussion or ping the squad. We're here to help.
